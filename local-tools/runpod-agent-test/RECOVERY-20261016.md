# Agent Trace 접속 오류 복구

2026-10-16 확인 및 적용.

- `Failed to load runtime state: Failed to fetch`: WSL에서 웹 서버의 8787 포트가 닫혀 있었음. 종료 원인은 현재 확보한 자료로 확정하지 못함.
- 실습 대상 접속 실패: WSL에서는 `172.18.0.2:8101` HTTP 200이지만 Docker 실행기에서는 타임아웃. 호스트의 `DOCKER-INTERNAL` 규칙이 내부 작업 브리지에서 다른 대역으로 향하는 패킷을 컨테이너 게이트웨이에 도착하기 전에 차단함. DROP 카운터 증가로 확인.

WSL `~/LuaN1aoAgent/src/connectivity/network-sandbox-manager.ts`에 작업 브리지 생성·복구·정리와 연동한 호환성 처리를 적용하고 `.env`에 `LUANNIAO_LINUX_BRIDGE_COMPAT=1`을 설정함. `DOCKER-USER`에서 동일 작업 브리지 안에 머무는 L2 프레임만 허용하며, 호스트를 통한 다른 브리지로의 직접 라우팅과 게이트웨이의 대상 범위 검사는 유지함. 헬퍼 컨테이너에는 NET_ADMIN만 부여하고 실행기 권한은 유지함. 정상 종료 시 규칙도 제거함. 비정상 종료 시 없어진 브리지 이름의 규칙이 남을 수 있음.

서버는 Node 25로 백그라운드 재기동했으며 Windows와 WSL 양쪽에서 `http://127.0.0.1:8787/` HTTP 200을 확인함. 인증 없는 API는 정상적으로 401을 반환함. 기존 세션 DB 4개는 보존됨. 브라우저의 기존 로그인 상태를 이용한 화면 로딩은 사용자가 새로고침하여 확인해야 함.

검증: 서버 TypeScript 빌드 성공, 관련 테스트 32개 통과. 테스트 파일 병렬 실행 시 같은 포트 풀을 사용하는 테스트가 충돌하므로 `--test-concurrency=1`로 검증함. 실제 수정된 수명주기로 실행기→게이트웨이→호스트 중계기→실습 사이트 HTTP 200, 범위 밖 테스트 주소 차단, 종료 시 규칙 제거 확인. 전체 취약점 연구 작업의 성공은 이 연결 검사에 포함하지 않음.

```bash
cd ~/LuaN1aoAgent
node --test --test-concurrency=1 --test-force-exit dist/test/network-sandbox-manager.test.js dist/test/host-egress-broker.test.js
node /mnt/c/Users/KSM/Desktop/Deeppoint/runpod-agent-test/check_agent_connectivity.mjs
```

현재 화면은 새로고침 후 기존 기록을 Load하고, 실패한 연구 작업은 새 실행으로 시작하면 됨. WSL 종료 후 웹 서버를 다시 실행하려면 Node 25 환경에서 아래 명령을 사용함.

```bash
cd ~/LuaN1aoAgent
npm run web -- --runtime-dir .agent-runtime/sessions --port 8787
```

수정 패치는 `linux-bridge-compat.patch`에 보존함. 로컬 설정 백업은 WSL 저장소의 `.env.bridge-compat-20261016.bak`, 원본 소스 백업은 `/tmp/luanniao-network-sandbox-manager.pre-bridge-compat.ts`. 기존 Dockerfile의 사용자 변경은 보존함.

참고: [Docker의 internal 네트워크와 컨테이너 라우터 문제](https://github.com/moby/moby/issues/47145).
