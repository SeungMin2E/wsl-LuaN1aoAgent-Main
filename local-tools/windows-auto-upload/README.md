# GitHub 자동 업로드

대상 폴더의 파일을 저장한 뒤 **60초 동안 추가 변경이 없으면 테스트 후 GitHub main 브랜치에 자동으로 커밋**합니다. 이 프로그램 폴더 자체는 업로드 대상이 아닙니다.

| 내 컴퓨터 폴더 | GitHub 저장소 |
|---|---|
| `C:\Users\KSM\Desktop\Deeppoint\ai-agent` | https://github.com/SeungMin2E/ai-agent |
| `C:\Users\KSM\Desktop\Deeppoint\해킹 툴 테스트 사이트` | https://github.com/SeungMin2E/ai-agent-tool-test-site |
| WSL Ubuntu-24.04 · `/home/ksm/LuaN1aoAgent` | https://github.com/SeungMin2E/wsl-LuaN1aoAgent-Main |

**2026-10-16 사용자 요청으로 ai-agent 자동 업로드를 다시 켰습니다.** ai-agent와 테스트 사이트 두 폴더 모두 변경 후 테스트를 통과하면 자동 반영합니다.

**같은 날 사용자 요청으로 WSL 에이전트 본체도 추가했습니다.** Windows 감시기가 WSL 공유 경로에서 소스를 읽고, 빌드와 테스트는 WSL 안에서 실행합니다. 원본 `origin` 연결은 유지하며 사용자 저장소의 `main`에 자동 커밋합니다. 이 방식은 로컬 Git 커밋 없이 저장된 파일을 업로드하므로 WSL의 `git status`에는 변경이 계속 표시될 수 있습니다. WSL 경로에 접근하지 못하면 해당 프로젝트의 업로드를 보류합니다.

`config.json`에서 프로젝트의 `"enabled": false`는 해당 폴더의 자동 업로드를 막습니다. Windows 재로그인이나 아래 켜기 명령으로 감시기를 다시 시작해도 유지됩니다. 수동 업로드 한 번을 요청받았다는 이유로 자동 업로드를 다시 켜지 않습니다. 설정 변경은 감시기를 중지한 뒤 적용하고 다시 시작해야 합니다.

## 사용

- **상태확인.cmd**: 실행 여부, 최근 업로드·오류 상태 확인.
- **자동업로드끄기.cmd**: 감시 중지 + 다음 로그인 시 자동 시작 해제. 이미 진행 중인 작업은 끝날 수 있습니다.
- **자동업로드켜기.cmd**: 감시 시작 + 다음 로그인 시 자동 시작 등록.

설치 후 이 PC에서 윈도우에 로그인하면 창 없이 시작합니다. PC가 켜져 있고 로그인되어 있어야 동작합니다. 인터넷이 끊기면 변경 내용을 유지하고 연결 후 다시 시도합니다. 이 대화나 VS Code가 열려 있을 필요는 없습니다.

GitHub 인증은 기존 GitHub CLI 로그인을 사용합니다. 로그인 정보는 이 폴더에 복사하지 않습니다. VS Code의 Git 저장소 연결과는 별개로 동작하며, GitHub 변경을 로컬 폴더로 내려받는 기능은 없습니다.

## 검증 및 예외 처리

ai-agent는 로컬 Python 단위 테스트를 실행합니다. Linux 전용 프로세스 테스트는 윈도우에서 건너뛰며, 업로드 후 기존 GitHub Actions에서 Linux 테스트를 실행합니다. 실제 RunPod GPU 구동은 자동 검증 대상에 포함되지 않습니다. 테스트 사이트는 기존 18개 테스트를 실행합니다. 테스트 사이트를 직접 실행 중이면 테스트 포트 충돌로 업로드가 보류될 수 있습니다.

WSL 본체는 `verify_wsl_agent.py`로 Go 트래픽 프록시 빌드, 서버·웹 빌드, 서버 테스트 전체(파일 간 포트 충돌을 피하도록 순차 실행), 웹 테스트 전체를 확인합니다. Node 25 이상을 사용자 nvm 설치에서 선택하며, Go는 사용자 전용 `~/.local/share/luanniao-build/go1.27.2/go/bin`을 사용합니다. 이 검사에서는 모델 추론이나 취약점 연구 작업을 시작하지 않습니다.

테스트 실패, 인증·네트워크 오류는 기록하고 5분 후 재시도합니다. 파일을 다시 수정하면 새 변경에 대해 60초를 기다립니다. 테스트 중이나 업로드 준비 중 파일이 바뀌면 새 내용으로 다시 검증합니다.

GitHub의 같은 파일이 따로 수정되어 있으면 덮어쓰지 않고 보류합니다. 강제 푸시는 하지 않습니다. 일반 파일 삭제는 반영하지만 대량 삭제와 비어 있거나 이동된 폴더는 보류합니다. 이름 변경은 삭제·추가로 반영합니다.

`.git`, 캐시, 가상환경, `results`, 로그, 실제 `.env*`, 개인 키와 토큰 파일은 제외합니다. 공개 설정 예시인 `.env.example`은 비밀정보 검사를 거쳐 포함합니다. `.agent-runtime`, `.agents`, `.runtime`, `.playwright-cli`는 순회하지 않으므로 세션 DB·트래픽·실행 기록을 업로드하지 않습니다. `.gitignore`의 일반 패턴과 하위 폴더 규칙도 반영합니다. `!` 예외 및 역슬래시 이스케이프 패턴은 검토가 필요하므로 자동 업로드를 보류합니다. 알려진 토큰·개인 키 형식도 검사하지만 모든 비밀 정보를 판별할 수는 없습니다. 파일당 8 MiB, 프로젝트 전체 40 MiB를 넘으면 보류합니다.

`state/status.json`에서 실행 상태를, `state/watcher.log`에서 업로드 및 오류 이력을 확인할 수 있습니다. 실패한 테스트 출력은 `state/*-tests.txt`에 남습니다. 로그는 크기에 따라 자동 순환합니다. `state/baseline.json`은 동기화 이력이므로 지우지 마세요.

세 저장소는 현재 공개 저장소입니다. 대상 폴더에 저장한 일반 소스 파일과 문서는 자동 공개됩니다. 다른 폴더는 감시하지 않습니다.
